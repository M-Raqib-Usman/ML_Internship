Abstract

This project asks which content pages should be prioritized for editorial review when editor time is limited. Using the anonymized FlyRank starter dataset (30,000 pages × 44 columns), a Random Forest model ranks pages by likelihood of decline. On a client-holdout validation split the model improves Precision@50 over a transparent hand-written rule (stale + visible), typically landing in a roughly 2–3× range depending on run. The output is a ranked action queue with reason codes intended as decision-support for human review, not automated content changes. All claims are observational and limited to this dataset and validation design.

1. Introduction / Problem

Content teams cannot review every page. The practical decision is ranking: which pages should be looked at first for refresh, CTR review, or monitoring? A fixed rule (for example “old + high impressions”) is easy to explain but quickly runs out of signal. This work builds a ranked queue from observable search and engagement signals and compares it honestly against that rule.

2. Data

  • Source: FlyRank ML Internship starter dataset — content_refresh_anonymized.csv
  • Size: 30,000 rows × 44 columns (one row per pseudonymized content item)
  • Clients: 32 pseudonymized clients
  • Window: trailing 90-day metrics
  • Excluded: client names, domains, URLs, titles, raw keywords (privacy). Also excluded label-derived fields (trend_pct, trend_direction) from features to avoid leakage.

Public-safe throughout: only pseudonymized IDs and aggregated metrics appear.

3. Methodology

Label

is_declining_label = 1 when trend_direction == "down" (observed outcome). Base rate ≈ 54%.

Features (knowable before decision)

content_age_days, days_since_last_update, impressions_90d, avg_position, ctr, word_count, engagement_rate, sessions_90d.

Baseline

Hand rule: stale (≥180 days since update) × visible (≥500 impressions) × impressions. Reason code: stale_but_visible. Action: refresh.

Model

Random Forest (n_estimators=200, max_depth=10, class_weight balanced_subsample). Ranked by predicted probability of decline.

Validation

Client-holdout split (GroupShuffleSplit on client_id). Same split used for baseline and model. Primary metric: Precision@50 (matches limited editorial capacity). Base rate always reported.

Leakage checks

  • No trend_pct / trend_direction as features
  • No product health/priority flags
  • Deliberate leak test: adding trend_pct pushes Precision@50 toward 1.0 — then removed

4. Results (vs baseline)

On the client-holdout test set the model ranks declining pages higher than the hand-written rule at the top of the queue. Exact numbers vary slightly by library version; the directional lift and the comparison design are the finding.

5. Limitations & honest framing

  • This is decision-support, not a guarantee that refreshing a page recovers traffic.
  • No claim is made about Google’s ranking algorithm.
  • One snapshot; patterns can differ across clients and time.
  • Low-volume pages produce noisy signals.
  • Client-holdout tests generalization across sites, not future time periods.

6. Ranked recommendations (Action Playbook)

Editors open the ranked list, read reason codes, and decide. Suggested actions:

  • refresh — stale and still visible, or high model decline risk
  • refresh_and_review_ctr — same + low CTR at a competitive position
  • monitor — lower priority

Reason codes: stale_but_visible, low_ctr_visible_page, model_decline_risk

Human review required. Never auto-publish, auto-delete, or act on near-zero-impression pages without judgment.
